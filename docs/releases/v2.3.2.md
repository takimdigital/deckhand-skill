# Deckhand 2.3.2 — a real field test and a full audit, fixed

A field test on a real Windows machine and a five-part audit of the whole skill found 62 problems. This release
fixes 51 of them, each with a test that failed before its fix:

- **Deploy finishes.** `dh deploy target --app … --url …`, the form the deploy guide gives, now saves the app and
  its address. Before, every deploy stopped at "no target". Deploy no longer counts its own record files as unsaved work.
- **Checkpoints hold.** A backdoor deploy command, a forced review and a broken project file can no longer get past
  a checkpoint. A review of older code doesn't count, and "ok, I'll look later" means wait, not go.
- **Your files are safe.** `dh scaffold --to .` no longer empties your folder. Building a page no longer overwrites
  section files another page uses. Undoing a theme or SEO change keeps edits you made after it.
- **Safer sources.** A starter site known to carry hidden code is never suggested or cloned. Copyleft and Commons
  Clause code is refused, even when served from a mirror, and community workflows can't hide shell tricks.
- **Try-on can't be taken over.** While try-on runs, no other website can reach it.
- **Windows.** The installer works on the PowerShell built into Windows, a second linked install no longer wipes
  your copy, and the tests pass there. A Windows test failure now blocks a merge and a release.
- **Secrets stay out of sight.** They can be set from a file, their values are never printed, and a public
  repository is refused for your private bases.

Still open, with proposed fixes in docs/field-tests/2026-09-29-report.md: the build step passes while planned pages
return 404 (F9); a clone overwrites the base's NOTICE and commits ignored files (F10); no navbar by default (F16);
demo prices and `href="#"` links are not flagged (F13); `seo apply` keeps a wrong `<html lang>` (F17); plus F2, F12,
F15, F19, F21 and F23.
