# Deckhand 2.3.1 — the pipeline does what its docs say

A review of the whole pipeline, from define to operate, checked every rule the docs state against the code.
Where the code did not hold a rule, it does now:

- **Checkpoints can't be approved early.** The go for a step is taken only once that step is done, so an agent
  can't approve the build while it is still building.
- **No skipping ahead.** Only the step the project is at can be skipped, and review never: an end-to-end run could
  skip review and go live without its checks. Clone, rebrand and deploy each wait for their turn.
- **You still see the design.** Skipping try-on no longer approves the look on your behalf: you are shown the
  rebranded site before review.
- **The next step fits your run.** In end-to-end mode Deckhand no longer says to wait for you. A from-scratch site
  is asked for its words at the plan step, and a missing words file gets a plain message instead of a crash.
- **Two checks that could not fail now can.** The example plan left untouched is refused, and research needs at
  least 3 quotes actually found on their pages.
- **Hermes-safe text.** Instructions and agent packages no longer carry `<x>` placeholders, which make Hermes refuse
  a whole batch of tasks.
