# v2.4.3 — a verify is not made stale by the files it writes itself

- **`dh deploy ship` no longer refuses a green verify because of deckhand's own notes.** `dh verify` writes SEO owner items to `PENDING.md`; committing them used to make the verify look stale (`VERIFY_STALE`). Deckhand's own files (`PENDING.md`, `HANDOFF.md`, `RESUME.md`) are now ignored by the staleness check; code changes still count.
